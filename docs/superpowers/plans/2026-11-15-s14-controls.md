# S14 — Contrôles aléatoires natifs Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Produire les références de timing S14 avec les vrais fills du Book, leurs statistiques et un bundle portable reproductible, admis par S12 et rendu strictement par PHP.

**Architecture:** Conserver la préparation Loaded/Shared et le chemin minute du portefeuille comme source unique de simulation. Une géométrie explicite prépare causalement les entrées ; research compte et échantillonne les calendriers individuels exacts, puis engine les rejoue ensemble. CLI vérifie/admet avant chargement et report publie les octets détenus ; PHP valide et affiche.

**Tech Stack:** Rust 1.97, structures BTree déterministes, num-bigint =0.5.1, SplitMix64 du dépôt, JSON canonique/BLAKE3 existants, Symfony 7.4/PHP 8.3 readonly/Twig/PHPUnit.

---

Ce document est un plan d'exécution de `docs/specs/s14.md`, pas une nouvelle conception. Seul le pilote commite/pousse. Chaque lot ci-dessous se termine par revue du diff et des tests, puis remise au pilote ; aucun agent ne commite. Les commandes partent de la racine du worktree. Aucune donnée réelle, campagne économique, clé ou lecture de `~/.kraken` n'est nécessaire. Ne pas lancer plusieurs Cargo concurrents sur le cache partagé ; `TMPDIR=/var/tmp` si le poste le requiert.

## Interfaces constatées et limites à respecter

- `tv4/src/engine/portfolio.rs` contient déjà `Loaded`, `Shared`, `Checked`, `load`, `share_research`, `play_profile`, `book_config` et `PrepStats` (visibilité `pub(super)`). `Shared` emprunte `Loaded` : garder une portée lexicale, pas de structure autoréférente ni Arc autour d'appels publics reconvertissant les colonnes. `LegRun`, `PlayBuffers` et `play` sont privés ; un enfant `portfolio/controls.rs` peut les utiliser sans les rendre publics.
- `play` impose : quote gaps, sorties d'univers, toutes expirations, Book::on_bar, marquage, tous contextes/stratégies, puis toutes soumissions. Le plafond Research réel est déjà C0/max_positions, malgré certains commentaires anciens « /N ».
- `sma_cross` 1.1.0 porte `prev_diff`, stop ATR14, croisement inverse et filtre trend optionnel ; `uses_regime()` hérité vaut false. Ne pas modifier version, paramètres, JSON, déclencheur observé ou funnel. Les appels qui ne clôturent que trend ne changent pas `prev_diff`.
- `report::verify::VerifiedRun` possède `metrics_bytes`, `trades_bytes`, `equity_bytes`, `manifest_bytes` et `stats_inputs().bytes`. `report::stats::snapshot` analyse ces octets, donne `TradeRecord { lot_id, symbol, entry_ms, exit_ms, r_multiple, included, ... }`. Les sources S14 exigent le paquet S13 et son TF cohérent. Book utilise snapshot.initial_cash du run vérifié (métriques/manifeste bit à bit), pas le C0 de marks du paquet si celui-ci diffère dans la tolérance admise.
- `engine::preflight::portfolio` calcule la vraie identité sans séries. `CostSetup`, `profiles::resolve_legs`, `ResearchRun`, `model::blocks::is_purged`, `RegimeSeries/RegimeFeed` sont à réutiliser. `report::research::split_trades` est dans report : engine utilise la règle model, pas un import remontant vers report.
- `cli::research::admission::Session::begin_with_prepare` fabrique aujourd'hui les ConfigSpec et impose une fiche commune ; `registry::Admission`/`propose_admission` impose aussi une HypothesisRef commune. Étendre ce chemin existant, pas un journal parallèle. Une admission S14 peut contenir plusieurs parents/fiches compatibles en DEV : le contrôle de fiche commune reste appliqué au chemin candidat ordinaire et aux blocs protégés.
- `report::profiles::{render_profile_research,RenderedProfile}` et `report::research::render_research_run` rendent les trois fichiers de simulation. Le rejeu Observed devra appeler le même rendu et les mêmes métadonnées historiques, sans substituer la nouvelle admission au contenu source.
- `verify::load_stats_leaves` reconnaît run/profiles/lines ; étendre cette reconnaissance pour controls. Le lecteur PHP `RunDirectoryReader` construit `RunReport(..., ?StatsReport)` ; lui ajouter un dernier champ optionnel controls conserve ses appelants historiques. `Tv4ReportCommand` choisit actuellement lines/profiles/run.

```rust
// research::controls::types, sans dépendance strategy.

pub enum ControlMode { PreserveBtc, RemoveBtc }

    pub quotas: std::collections::BTreeMap<String, Vec<AnnualQuota>>,
    pub observed_score: Option<f64>, pub observed_months: Vec<MonthMoment>,
    pub modes: Vec<ModeSummary>,
}

    pub mode: ControlMode, pub alias_of: Option<ControlMode>,
    pub catalogues: Vec<PairCatalogue>, pub cells: Vec<CellSummary>,
```

`CellSummary.availability` est CellAvailability ; `PanelStatistics.status` est PanelStatus. `ModeStatistics { mode:ControlMode, alias_of:Option<ControlMode>, panel:PanelStatistics }`. `ProgramBudgets` est la projection sérialisable des cinq budgets propres, appliqués par géométrie/programme ; le plafond global d’invocation est gardé dans Budgets et ControlRunIdentity seulement. `summarize_panel` prend une seule matrice d'un mode effectif et renvoie PanelStatistics ; BatchOutcome.statistics contient modes distincts et aliases explicitement liés. `EntryIntervention` du contrat strategy est mappé explicitement depuis ControlMode dans engine (pas d'import research dans strategy). `CellSummary.replay_trace_hash` est calculé avec model::hash sur les événements numériques canoniques (calendriers, fills, libérations, statuts et quantités), après validation, sans report. Le champ public final `replay_hash` appartient au DTO report et combine ReplayIdentity, tentative et replay_trace_hash. Engine ne dépend pas de report ; il rend cette empreinte de trace et le numéro de tentative, pas une fausse identité complète.

Le callback validate_observed ne conserve pas PortfolioResult ; il rend/compare immédiatement les trois octets, puis ils sont libérés. Un ObservedMismatch attendu devient BatchOutcome inconclusive avec reason ObservedMismatch ; seules les erreurs de rendu/I/O/corruption arrêtent avec code1. Son résultat utilise donc une enum `ObservedValidation { Matched, Mismatched }`, et sa signature finale est `FnMut(usize, ObservedRun<'_>) -> Result<ObservedValidation, String>` ; toute chaîne Err est technique.
